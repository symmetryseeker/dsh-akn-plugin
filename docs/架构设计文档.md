# 1. 概述与目标

`dsh-akn-plugin` 是一个植入 DeepSeek Harness (DSH) 的原生 Cordis 插件，实现 **Agent Knowledge Network (AKN)** 协议。其核心主张是：

> **工具调用即知识采集**：Agent 的每一次工具调用（成功或失败）都被自动捕获为一条结构化、内容可寻址、可验证、不可变的知识对象 (Knowledge Object, KO)，进入共享知识网络。

AKN 因此成为所有 DSH Agent 的**共享记忆基底**与**协作总线**——任何 Agent 可以发布知识、检索知识、验证知识；一个 Agent 的失败经验可被另一个 Agent 复用；一个被证伪的事实会级联失效其全部依赖者。

三个定位关键词：

| 定位 | 含义 |
|---|---|
| **共享记忆基底** | 内容可寻址 + 不可变，天然去重、可溯源，成为跨会话、跨 Agent 的持久知识层 |
| **协作总线** | 悬赏 (task-intent) 与验证 (verification) 构成发布-验证-消费的协作回路 |
| **可插拔验证** | 信任不依赖发布者权威，只依赖可复现的验证记录 |

# 2. 设计原则（代码评审的"宪法"）

以下四条铁律约束所有模块的实现，任何偏离都需要显式的设计豁免：

1. **结构化优先于文本** — 知识对象必须通过 Zod Schema 严格校验，绝不接受无 Schema 的松散 JSON。`body` 使用 `z.discriminatedUnion('type', ...)`，由 `type` 字段驱动解析，杜绝结构歧义。

2. **内容可寻址且不可变** — `KO.id = sha256(JSON.stringify(body))`。修改 body 即得到新 ID，旧版本保留溯源。**验证与状态属于元数据，不参与内容寻址**（因此 verify 不会改变 KO 的 id）。

3. **高信噪比（Token Economy）** — `akn_search` 默认只返回 `id, title, summary, status, environment`，**默认严禁附带庞大的 body 字段**，除非显式传参 `includeBody: true`。

4. **验证与内容分离** — 信任不依赖发布者权威，依赖可复现的 `verification` 记录（含 verifier DID、判定、证据、时间戳）。

5. **失效传播（Cascade Invalidation）** — 维护依赖反向索引，上游被证伪后，其全部直接/间接下游自动变更为 `needs_verification`。

`Storage → Service → Tools → Listeners → 种子注入 → ctx.provide('akn')`

该顺序保证：业务层可用后才暴露给工具与监听器；种子注入仅在 `storage.size() === 0` 时执行（幂等冷启动）。

# 4. 数据模型（core/types.ts）

## 4.1 status 枚举

```ts
export const AKN_STATUS = [
  "draft", "proposed", "verified",
  "refuted", "stale", "needs_verification",
] as const;
```

生命周期语义：

| 状态 | 语义 |
|---|---|
| `draft` | 草稿，未进入协作流 |
| `proposed` | 已发布待验证（自动采集的默认态） |
| `verified` | 通过至少一次正向验证 |
| `refuted` | 被证据证伪 |
| `stale` | 环境漂移，可能不再适用 |
| `needs_verification` | 上游被证伪/依赖失效，需重新验证 |

## 4.2 environment

```ts
export const AknEnvironmentSchema = z.object({
  os: z.string(),                          // 如 "win32 x64 (node v24.14.1)"
  toolVersions: z.record(z.string(), z.string()), // { node: "v24.14.1", glob: "10.4.0" }
  dataTime: z.string().optional(),         // ISO 观察时刻
});
```

`dataTime` 可选；`os` 与 `toolVersions` 必填。这是**环境漂移检测**的事实来源。

## 4.3 links（依赖图）

```ts
export const AknLinksSchema = z.object({
  basis: z.array(z.string()).default([]),   // 我依赖的上游 KO id
  refutes: z.array(z.string()).default([]), // 我证伪的目标 KO id
});
```

- `basis`：声明了"我的结论继承自哪些事实" → 驱动反向索引与级联失效。
- `refutes`：声明了"我反驳谁" → 驱动对抗性知识网络（counter-evidence）。

## 4.4 body 判别联合

```ts
export const AknBodySchema = z.discriminatedUnion("type", [
  ToolCallRecordV1,     // { type:"tool-call", toolName, input, output, durationMs, ok, error? }
  NegativeKnowledgeV1,  // { type:"negative-knowledge", toolName, error, stack?, mitigation? }
  TaskIntentV1,         // { type:"task-intent", intent, criteria[], reward? }
]);
```

判别联合保证：`body.type` 与其余字段严格匹配，拒绝松散 JSON。三种变体覆盖"成功经验 / 失败教训 / 协作悬赏"三类知识。

## 4.5 KO 完整 Schema

```ts
export const AknCommonMeta = z.object({
  id: z.string().regex(/^[0-9a-f]{64}$/),   // sha256(body) 的内容寻址
  title: z.string().min(1),
  summary: z.string().min(1),               // 检索投影的正文（Token Economy 关键）
  body: AknBodySchema,
  status: AknStatusSchema,
  environment: AknEnvironmentSchema,
  links: AknLinksSchema,
  verifications: z.array(VerificationV1).default([]), // 只追加验证链
  tags: z.array(z.string()).default([]),              // 分类标签
  source: AknSourceSchema.optional(),                 // { agentId?, capture? }
  createdAt: z.string(),                              // ISO
  updatedAt: z.string(),                              // ISO，仅 meta 变更时更新
});
export type KO = z.infer<typeof AknCommonMeta>;
```

**关键不变式**：`id` 只由 `body` 决定；`status`/`verifications`/`tags` 是可变元数据，不参与寻址。这保证了"验证动作不改变内容的地址"。

# 5. 存储层（core/storage.ts）

## 5.1 数据结构

```ts
export class MemoryStorage implements IAknStorage {
  private store = new Map<string, KO>();             // id → KO（内容寻址，不可变内容）
  private reverseIndex = new Map<string, Set<string>>(); // 上游id → Set<下游id>
}
```

## 5.2 反向索引维护（save 时）

```ts
save(ko: KO): void {
  this.store.set(ko.id, ko);
  for (const basisId of ko.links.basis) {
    // 建立"谁依赖了我"
    let bucket = this.reverseIndex.get(basisId);
    if (!bucket) { bucket = new Set(); this.reverseIndex.set(basisId, bucket); }
    bucket.add(ko.id);
  }
}
```

**时间点选择**：在 `save()` 同步维护，而非惰性扫描——保证级联失效时 `dependents(id)` 是 O(1) 读。

## 5.3 检索

`search(query)` 支持多字段过滤：`type`、`status`（单值或数组）、`tags`（任一命中），以及 `keyword` 对 `title + summary` 的 `includes` 不区分大小写匹配。

# 6. 服务层（core/service.ts）

## 6.1 publish —— 发布流程

```
输入 raw
  │  PublishInputSchema.parse(raw)      [宪法校验，失败即抛]
  ▼
id = sha256(canonicalJson(body))        [内容寻址，canonicalJson 对 key 排序保证确定性]
  │
  ├─ 遍历 links.basis 的上游 KO：
  │    若任一上游 status === "refuted"
  │      → status 强制覆盖为 "needs_verification"   [继承污染，标记 inheritedInvalidation=true]
  │
  ▼
构造 KO（createdAt/updatedAt=now, verifications=[]）
  → storage.save(ko)
  → 返回 { id, status, inheritedInvalidation, ko }
```

**canonicalJson 说明**：`JSON.stringify(body)` 对对象 key 顺序敏感；同语义不同 key 顺序会产生不同 id。因此实现 `sortKeys` 递归排序，使内容寻址与序列化顺序无关（对规约的健壮化，不改变规约语义）。

## 6.2 search —— 硬排序

排序权重表（来自 `cordis.patch.yml` 可配置，默认）：

| status | 权重 | 说明 |
|---|---|---|
| `verified` | 0 | 已证实，最可信，永远置顶 |
| `proposed` | 1 | 待验证 |
| `needs_verification` | 2 | 依赖失效 |
| `stale` | 3 | 环境漂移 |
| `draft` | 4 | 草稿 |
| `refuted` | 5 | 已证伪，垫底 |

可选 `options.driftCheck`：返回前对命中 KO 做环境漂移检查，漂移者自动降级 `stale`。

## 6.3 verify —— 验证与级联失效

```ts
verify(targetId, verifierDid, verdict, evidence): VerifyResult {
  const ko = storage.get(targetId);            // 拉取目标
  const v: VerificationV1 = { verifierDid, verdict, evidence, createdAt };
  storage.save({ ...ko, status: verdict ? "verified" : "refuted",
                 verifications: [...ko.verifications, v], updatedAt });
  const invalidated = verdict ? [] : this.propagateInvalidation(targetId);
  return { ko: updated, verification: v, invalidated };
}
```

**级联失效算法**（BFS over reverseIndex，含间接依赖）：

```
propagateInvalidation(rootId):
  queue = [rootId]; visited = {rootId}; changes = []
  while queue 非空:
    current = queue.dequeue()
    for dep in storage.dependents(current):        // 谁直接依赖 current
      if dep in visited: continue
      visited.add(dep)
      downstream = storage.get(dep)
      if downstream.status === "needs_verification": continue   // 已失效跳过
      storage.save({ ...downstream, status: "needs_verification", updatedAt })
      changes.push({ id: dep, from: 原状态, to: "needs_verification" })
      queue.enqueue(dep)                          // 继续向下一层传播
  return changes                                  // 变更日志（供工具返回给 Agent）
```

该算法保证**间接依赖**（A 依赖 B，B 依赖被证伪的 C → A 也被降级）被完整覆盖，且对已失效节点幂等。

## 6.4 环境漂移检测

```ts
detectDrift(id, currentEnv): DriftReport | undefined {
  // 对比 ko.environment.toolVersions 与 currentEnv.toolVersions
  // 任一工具版本不一致 → 记录 {tool, recorded, current}
  // 若有差异：storage.save({ ...ko, status: "stale", updatedAt }) 并返回报告
}
```

# 7. 工具层（tools/*）

## 7.1 akn_search —— 默认截断 body

```ts
execute(args) {
  const hits = service.search({ filters, keyword }, { limit, driftCheck, currentEnv })
    .map(ko => includeBody
      ? { id, title, summary, status, environment, body }   // 显式 includeBody=true
      : { id, title, summary, status, environment });        // 默认：无 body（Token Economy）
  return { count, hits };
}
```

**默认投影字段**：`id, title, summary, status, environment`。`environment` 展开为 `{os, toolVersions, dataTime}`，不携带 body。参数 `limit` 缺省时取配置 `searchDefaultLimit`（默认 20）。

## 7.2 akn_publish

```ts
execute(args) {
  service.publish({
    title, summary, body,
    environment: args.environment ?? service.currentEnvironment(), // 缺省快照当前环境
    links, tags, status,
  });
  return { id, status, inheritedInvalidation };
}
```

## 7.3 akn_verify

```ts
execute(args) {
  service.verify(args.targetId, args.verifierDid, args.verdict, args.evidence);
  return { targetId, status, verifications: 数量, invalidatedCount, invalidated: [{id,from,to}] };
}
```

`verdict=false` 会触发级联失效，返回值携带全部受影响下游的变更日志。

# 8. 监听层（listeners/auto-capture.ts）—— 杀手级特性

## 8.1 事件捕获

| 事件 | 捕获 | 产出 KO |
|---|---|---|
| `tool/after` | `toolName, input, output, durationMs`（无 error 时） | `ToolCallRecordV1`，`status: proposed`，`ok: true` |
| `tool/error` | `error, stack?, mitigation?` | `NegativeKnowledgeV1`，`status: proposed` |

## 8.2 三条保护规则

1. **异常隔离**：每个 handler 整体包裹 `try-catch`，采集异常仅 `console.warn`，**绝不 throw 进 Agent 主流程**。
2. **自我递归防护**：跳过 `SKIP_TOOL_NAMES = {akn_search, akn_publish, akn_verify}`——避免 AKN 工具自身被反复采集成噪声/无限循环。
3. **内容寻址去重**：相同 body → 相同 id → 存储不膨胀。自动采集天然幂等。

## 8.3 summary 的 Token Economy

自动采集生成的 `summary` 截断到 320 字符，形如 `fs.readFile ok: {...}` / `FAILED fetch: timeout...`，保证检索投影短小。

# 9. 冷启动与种子（bundles）

## 9.1 seed.ts —— 23 条对抗种子

覆盖真实跨平台陷阱，成功/失败约各半：fs.readFile 编码、glob 反斜杠、fetch 无超时、连接池耗尽、JSON 尾逗号、chmod EPERM、spawn ENOENT、POSIX 反斜杠、crypto 算法、ReDoS、NODE_ENV 未定义等。

**内嵌级联演示链**：

```
[glob-backslash-negative]  --refutes-->  [glob-backslash-ok?]    (无，演示 refutes 元数据)
              │ basis
              ▼
   [use-fwd-slash-workaround]  （"跨平台用正斜杠" 的指导性 KO）
```

种子构建时用 `hashBody()` 预计算 body 的 id 并回填 `links.basis`，保证依赖链指向真实 id。冒烟测试验证：refute 上游 → 下游自动 `needs_verification`。

## 9.2 tasks.ts —— 3 条悬赏 intent

| 悬赏 | 意图 | 验收标准 |
|---|---|---|
| glob 种子在 win32 复验 | 重现正/反斜杠种子并提交证据 | 附加实际匹配数；可复现则 refute |
| fetch 无超时的工作区 | 产出 AbortSignal 包装 + 通过测试 | 附带失败→通过的测试证据；第二 Agent 验证 |
| 负例种子的版本漂移审计 | 重跑 11 条失败种子，漂移者标 stale | 记录 toolVersions；至少 1 条 stale + 修正 KO |

# 10. Cordis 集成（src/index.ts）

## 10.1 apply 装配

```ts
export function apply(ctx, rawConfig = {}) {
  const config = { ...DEFAULTS, ...rawConfig };
  const storage = new MemoryStorage();                 // ①
  const service = new AknService(storage, resolveEnv); // ② 环境解析：ctx.runtime → process 回退
  registerAknTools(ctx, service, { searchDefaultLimit }); // ③
  mountAutoCapture(ctx, service, { autoPublish });       // ④
  if (bootstrapSeeds && storage.size() === 0) publishAll(seedKOList);  // ⑤ 幂等
  if (bootstrapTasks) publishAll(taskKOList);
  ctx.provide("akn", service);                          // ⑥ 协作总线
  ctx.akn = service;                                    // 双保险运行时挂载
}
```

## 10.2 服务暴露与模块增强

```ts
declare module "@deepseek-ai/cordis" {
  interface Context { akn: AknService; }
}
```

任何其他 DSH 插件可直接 `ctx.akn.search(...)` 消费 AKN，无需感知本插件内部实现——这是"协作总线"的类型化入口。

## 10.3 环境解析（ctx.runtime → 回退链）

优先读取 `ctx.runtime.os / toolVersions / versions`；缺失时回退 `buildEnvironment()`（基于 `process.platform / arch / version`）。这使服务层在 DSH 之外（如纯 Node 测试）也能独立运行。

## 10.4 类型兼容策略

cordis 的 `ctx.on` 按其已知事件映射表类型化，但 dsh 运行时注入的 `tool/after`、`tool/error`、`tools` 服务、`dispose` 生命周期事件不在全部发布版本的公开类型面中。因此：

- 提供 `onEvent(ctx, name, handler)` 辅助函数，将 `ctx.on` cast 为 `(event: string, handler) => void`；
- 通过结构 cast 访问 `ctx.tools.register`。

运行时行为不变，编译期兼容各 dsh 版本。

# 12. 边界情况与质量自检

| 自检项 | 结论 |
|---|---|
| reverseIndex 是否在 save 时维护 | ✅ 是，级联失效 O(1) 读 |
| akn_search 是否默认截断 body | ✅ 默认仅 `{id,title,summary,status,environment}` |
| tool/after 监听是否 try-catch 隔离 | ✅ 每个 handler 独立包裹 |
| 验证失败是否级联改下游 | ✅ BFS + 变更日志，间接依赖也覆盖 |
| 是否用 node:crypto 计算 SHA256 | ✅ `createHash('sha256')` + canonicalJson 确定性序列化 |

已识别的边界情况：

1. **同 body 不同 title 的碰撞**：`id=hash(body)` 下两者共享地址，后写 meta 覆盖先写（内容寻址的固有语义，需在文档中明确）。
2. **自我采集循环**：AKN 自身工具被 SKIP 集合排除。
3. **超大 output**：summary 截断 320 字符；完整 body 需显式 `includeBody`。
4. **已失效节点重复命中**：级联对 `needs_verification` 幂等跳过，避免重复降级。

# 13. 评审修订方案（安全与生产化）

> 依据外部评审（评分 9.2/10）的三个风险点给出修改方案。本节为**设计层面方案**，落地时另出实现计划。

## 13.1 风险点 1：verifierDid 信任锚缺失 —— 必须改正

**现状**：`verify` 仅记录 `verifierDid` 字符串，无签名校验，恶意 Agent 可伪造 `did:alice` 证伪他人成果。

**方案：本地信任锚 + 分层启用**

| 项 | 设计 |
|---|---|
| Schema 扩展 | `VerificationV1` 增加 `pubKeyFingerprint: string`（sha256(公钥DER)）与 `signature: string`（base64 Ed25519 签名），均必填；`verifierDid` 结构化为 `did:akn:<fingerprint>` |
| 验签门禁 | 签名负载 = `canonicalJson({ targetId, verifierDid, verdict, evidence, createdAt })`；`verify()` 前置校验 ① fingerprint 与 verifierDid 后缀一致 ② `crypto.verify("ed25519", payload, pubKey, signature)` 通过；任一失败即拒绝（抛错、不落状态、不触发级联） |
| 本地身份锚 | 新增 `core/identity.ts`；首次启动在 `$DSH_HOME/akn/identity` 生成 Ed25519 密钥对；Agent 注册公钥（anchor 背书），注册表持久化（SQLite `verifiers` 表） |
| 分层信任 | Tier-0 `requireSignature:false`（联调）；Tier-1 `requireSignature:true`（建议默认，指纹+本地注册表）；Tier-2 外部 DID 解析，仅留 `verifyIdentity(pubKey)` 端口 |

**零新依赖**：node:crypto 原生支持 Ed25519。

## 13.2 风险点 2：纯内存存储 —— 必须改正（最高优先）

**现状**：内存 Map，10 万条 KO 会爆内存，且重启丢失全部"肌肉记忆"。

**方案：SQLite 适配器（IAknStorage 端口已就绪）**

| 项 | 设计 |
|---|---|
| 新增模块 | `core/sqlite-storage.ts`，依赖 `better-sqlite3`（同步、嵌入式、零配置） |
| 表结构 | `kos(id PK, ko_json, body_type, status, created_ts)`；`ko_links(upstream, downstream, PK(up,down))`（反向索引持久化）；`verifiers(fingerprint PK, pubkey, agent_id)` |
| 索引 | `(status)`、`(body_type)`、`(body_type,status)`、`ko_links(upstream)` |
| 行为 | `save()`=UPSERT kos + 重写 links；`dependents()`=`SELECT downstream FROM ko_links WHERE upstream=?`；`search()`=动态 WHERE + ORDER BY statusRank + LIMIT；KO 以 JSON 列存储 |
| 配置 | `akn.storage: "sqlite"`（默认，memory 保留为 debug/单测回退）、`akn.storagePath: "$DSH_HOME/akn/akn.sqlite"` |
| 演进 | `PRAGMA user_version` 管理 schema 版本 |

**工作量修正**：评审估"100 行"偏乐观，实际约 150–250 行（需维护反向索引表与动态 SQL）。

## 13.3 风险点 3：浅层语义检索召回 —— 要改，但向量化优先级下调

**现状**：`includes` 关键词匹配，对模糊提问（"大文件内存溢出" vs 种子"处理 Buffer 堆栈"）漏召回。

**对评审的两点修正**：
1. 因 KO 内容可寻址，嵌入向量可**惰性回填**（搜索时缺向量补算），不存在"现在不存将来无法迁移"。
2. 存入即嵌入需先跑 BGE-small（~100MB 模型），与零配置目标冲突。

**方案：保留槽位 + 零依赖召回优化先行**

| 阶段 | 设计 |
|---|---|
| 槽位预留 | SQLite 侧表 `embeddings(ko_id PK, vector_json, model, dim)`，不侵入 KO 本体 |
| Tier-1（当前） | 查询规范化（小写/去标点/分词）；**别名扩展表** `AKN_ALIASES`（内存溢出↔OOM↔Buffer↔堆栈、超时↔timeout↔挂起），检索与索引双向展开；`summary` 建 n-gram（bigram/trigram）索引支持模糊子串 |
| Tier-2（未来） | 配置 `akn.embedder`（BGE-small），`akn_search options.semantic:true` 余弦检索，缺嵌入惰性回填，无需重建存量 |

## 13.4 落地顺序（P0→P2）

1. **P0** 签名验签（风险点 1）——纯核心层，改动集中。
2. **P0** SQLite 持久化（风险点 2）——用户留存关键。
3. **P1** 别名扩展 + n-gram 召回优化（风险点 3 廉价部分）。
4. **P2** 向量检索（槽位已留，静待升级）。

# 14. 项目价值评估

> 基于当前内容（架构文档 + 已实现并通过 14 项冒烟测试的源码）的客观评估。

## 14.1 一句话定位

把"工具调用即知识"固化为协议层的 DSH 插件——把 Agent 知识变成内容可寻址、可验证、依赖感知的协作资产，而非又一块"记忆存储"。

## 14.2 需求价值（痛点真实性）：高

| 痛点 | 真实性 | 项目对位 |
|---|---|---|
| Agent 重启即失忆 | 极真实 | 自动采集 + 持久化（SQLite 方案） |
| 知识不可信（幻觉经验） | 真实 | 验证与内容分离 + 级联失效 |
| 重复踩坑 | 真实 | NegativeKnowledge 失败知识共享 |
| Token 成本失控 | 极真实 | slim 投影 + summary 320 字符截断 |

## 14.3 设计价值（技术质量）：高——最强项

- **内容寻址不可变**：`id=sha256(body)` 天然去重 + 溯源，优于主流记忆系统的 UUID 方案。
- **依赖感知级联失效**：最大竞争壁垒。主流 agent 记忆方案普遍缺少"证伪上游→自动降级下游"的图传播——AKN 把知识当**网络**而非文档。
- **Token Economy 默认截断**：直接对标成本痛点，实测验证。
- **IAknStorage 端口抽象**：为 SQLite/向量后端预留干净替换点。
- **自动采集 + 自我递归防护**：杀手级特性；SKIP 集合防自我污染是实战细节。

## 14.4 生态契合度：高潜力，未验证

契合 DSH 多 Agent 生态对"共识层"的缺位；`ctx.provide('akn')` 接法正确。但 DSH 为高速迭代预览项目，插件生态爆发式增长，"设计得好"≠"会被用"。

## 14.5 成熟度：短板所在（详见第 15、16 章）

未挂载真实 DSH 端到端验证；纯内存（重启丢记忆）；verifierDid 无签名；keyword 检索漏召回；无规模化验证。

## 14.6 综合评分

| 维度 | 权重 | 得分 | 加权 |
|---|---|---|---|
| 需求真实性 | 20% | 8.5 | 1.70 |
| 设计质量 | 25% | 9.0 | 2.25 |
| 差异化/壁垒 | 20% | 8.5 | 1.70 |
| 生态契合 | 15% | 7.0 | 1.05 |
| 落地成熟度 | 20% | 4.5 | 0.90 |
| **总分** | | | **7.6 / 10（B+，高潜力待证明）** |

**结论**：护城河是"级联失效 + 内容寻址 + Token Economy"的组合；当前价值沉淀在**架构资产**上，产品价值需在 P0（签名、SQLite）落地 + 一次真实端到端演示后兑现。
