# Contributing to AEN — Draft/Pilot

AEN is an experimental protocol and reference implementation. Contributions are welcome, but merging code or an Experience does not make AEXP a stable standard and does not prove an Experience claim correct.

## Before opening a change

1. Read the [AEXP 0.1 specification](./spec/AEXP-0.1.md), the [MVP Implementation Profile](./spec/AEN-MVP-implementation-profile.md), and any relevant ADR.
2. Link the relevant `MVP-*` and full-Spec requirement IDs in the pull request.
3. Keep one pull request focused on one capability. Protocol field or semantic changes require an ADR plus synchronized specification, Schema, conformance, migration, and implementation changes.
4. Never commit real credentials, raw private traces, system prompts, customer content, local databases, generated publisher private keys, or unlicensed skill bodies.

## Local setup

Requirements are Node.js 22 or newer and pnpm 11.19.0.

```sh
pnpm install --frozen-lockfile
pnpm typecheck
pnpm test
pnpm conformance
```

When protocol schemas change, run `pnpm schemas:generate` and include the generated schemas and fixtures. A pull request is not complete if it only changes TypeScript while leaving wire schemas stale.

## Contribution types

- Protocol/core changes must preserve canonical digest, immutable revision, H-level, Promotion, visibility, and required-capability semantics.
- Harness Adapters must follow the [Adapter authoring guide](./docs/guides/adapter-authoring.md) and pass the same protocol validators as the sample and DSH adapters.
- DSH plugin changes must use authoritative DSH capability seams, remain removable through Cordis disposal, and keep ordinary tool-call synchronous AEN I/O at zero.
- Experience contributions must follow the [Experience authoring and review guide](./docs/guides/experience-authoring-review.md). Public contribution directories are generated by Promotion and reviewed through Git; do not hand-edit object digests.
- Security findings should not be opened as public issues. Follow [SECURITY.md](./SECURITY.md).

## Pull request evidence

Include commands and real outputs for typecheck, unit/contract/integration tests, affected DoD items, threat-model changes, rollback behavior, and any performance or security result. Clearly label synthetic fixtures, recorded runs, and live runs. Mock-only evidence cannot be presented as a real Harness, network, database, or model pilot.
